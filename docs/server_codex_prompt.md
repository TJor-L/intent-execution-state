# UCSF 服务器端 Codex 交接提示词

请在 UCSF 授权服务器上的 `intent-execution-state` 仓库内执行本轮工作。
本次预期 Git 提交：`{{COMMIT_SHA}}`

本轮是**一致来源／键探查接口的能力与设计审核**。当前代码只新增了规划预算诊断，
新读取器尚未实现。本轮不要提交新的真实可行性任务、重跑独立前缀扫描、扩大配额、
建立持久化索引或生成一致数据提取。先确认现有基础设施能支持哪种有界访问方式。

## 1. 核验版本与合成流程

- 阅读 `AGENTS.md`、`README.md`、`docs/15_privacy_security.md`、
  `docs/22_bounded_feasibility.md`、`docs/24_bounded_run_findings.md` 和
  `docs/25_coherent_access_design.md`。
- 检查 `git status --short` 和 `git rev-parse HEAD`。代码必须干净且完整 SHA 与上方
  一致；不要 reset、强制 checkout 或覆盖服务器工作。用户负责 pull。
- 依照获准环境运行 `make setup`、`make check`、`make demo`。不能安装依赖时记录
  不含私有内容的限制；不要把合成验证描述为临床结果。
- 保留现有私有 mapping、remote 配置、证据材料和两个 limited 报告；不要复制到 Git。

## 2. 检查新的无数据规划诊断

在服务器使用现有已审核的 version 2 映射：

```bash
uv run ies feasibility plan --mapping configs/feasibility.local.yaml
```

这个命令只读取配置，不访问源数据、不创建输出、不提交任务。检查 `identity_budget`
中的最大注册键需求、共享容量、缺口和 `all_source_row_caps_fit`。
原示例 3 × 5,000 行可需 15,000 个注册键，超过 10,000 的共享上限；新版示例把
每源行数降为 3,000，未扩大其他额度。已有服务器配置不会自动修改，请保留它。

`sampling: independent_source_prefixes` 与
`coherent_linkage_coverage_verified: false` 是明确限制。即使预算容纳得下，也不说明
三个独立前缀有共同身份覆盖。两次 limited 报告不能用于推断缺乏真实关联或无给药。
本轮无须为了消除诊断而再跑一次任务。

## 3. 审核已有能力，选择可实现的访问接口

依据已有获准文档、目录/索引说明和先前受限审核材料，核实以下事项；不要通过新建
全源键扫描或尝试大量 shard 来找答案。只在服务器私有审核记录中写实际引用和路径。

1. **种子与身份域**：是否有明确的现成医嘱种子来源、可复现的选择规则、已审核的
   身份域和共同快照？不得按成功 join 后的结果挑选种子。覆盖还须包括种子位置以外
   的重复医嘱记录；种子选取本身不构成总体代表性。
2. **现成一致来源**：是否已有单独获准的文件/row-group 清单，能证明覆盖种子医嘱
   的所有相关医嘱、给药和观测记录？不是临时挑几个看似匹配的文件。本轮不创建提取。
3. **现成索引／探查**：若没有一致来源，是否已有获准的精确键定位能力？需要针对
   order_id 找全相关给药，并针对 observation_id 找全观测记录；患者、动作和时间
   条件不能提前过滤掉重复、患者不符、回填或窗口外给药。还需确认医嘱本身的重复。
4. **可证明的完整性**：后端能否区分完整空结果、分页未完、截断和失败？是否可以
   证明所有请求键都查完，而非仅报告返回了多少行？找不到但覆盖不全应计 unresolved。
5. **工作量**：能否在读取前约束文件、row group、扫描行、保留行、身份键、探查次数、
   索引页和读取字节？SQL LIMIT、少量返回行或客户端超时不能代替物理工作量上限。
   不支持这些约束的远程查询也不能伪装成有界探查。
6. **版本与证据**：已有来源／索引是否有不可变 generation 和覆盖证明，能够绑定
   清单里的文件与内容？映射和清单须分别用实际字节 SHA-256 固定；只有清单哈希、
   文件大小或 mtime 不能证明底层数据未变。不要为补证据新做全文件哈希或键扫描。
7. **落盘边界**：后端能否在内存中处理键与行、不自动 spill、不落持久化索引／缓存？
   如果必须准备新索引或一致提取，提出单独范围和成本估计，本轮不要执行。

设计中的候选限额用于审核，不是已经实现的配置项。请不要把它们添加到现有 version 2
映射来尝试运行。新接口的生产读取、调度、覆盖回执和双校验和执行绑定仍需下一轮实现。
